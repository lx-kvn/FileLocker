# FileLocker GUI 造型探索——密碼庫「筆記本」方向定案

## 背景

信封（加密/清單/解密）、金庫門（資料夾防護）兩個方向定案後，密碼庫這輪延伸第三種視覺語彙——原因是密碼庫的操作性質（查閱、記錄、翻找）跟前兩者完全不同：信封是「裝東西寄出」、金庫是「限制空間進出」，密碼庫則是「持續查閱/記錄的筆記」，硬套前兩者的比喻都不合適，需要獨立的語彙。

密碼庫實際功能結構（`packages/password-locker-ui/src/PasswordLockerPage.vue`）：兩個分類（`Website` 網站帳密／`EncryptedFile` 已加密檔案）、每筆帳密可選配 TOTP（既有一組圓環倒數邏輯 `totpRingStyle`）、可關聯多個網域、有搜尋/排序、新增編輯表單。這份文件記錄跟使用者討論筆記本方向時，一輪一輪來回調整、邊討論邊畫的決策脈絡。

## 決策記錄

| 決策點 | 結論 | 理由 |
|---|---|---|
| 密碼庫的視覺語彙 | **筆記本**（螺旋線圈裝訂＋橫線內頁） | 密碼庫是查閱/記錄性質，跟信封「寄出」、金庫「限制進出」的動作性質不同，需要獨立的第三種語彙 |
| 整體容器要不要畫成闔上的封面 | **不要，直接用打開的內頁**（螺旋線圈＋米白橫線紙，中性色） | 最早畫過深咖啡皮革封面（含「PASSWORD NOTES」字樣），但深色封面當整頁背景，跟上面要疊的搜尋框/清單/表單這些高資訊密度控制項對比不夠、可讀性有風險；米白橫線內頁淺色、對比度好，撐得住功能性 UI；封面上烤死的英文字也違反雙語規則（所有文字要走 `t('key')`），標題交給前端疊字 |
| 內頁橫線的附帶用途 | 如果清單列高度跟橫線間距一致，**清單分隔線可以直接借用橫線本身**，不用另外疊 CSS `border-bottom` | 避免「畫一個筆記本樣子的背景」+「另外浮一層普通表格」這種兩張皮的違和感 |
| 兩個分類的顏色 | **網站帳密＝黃銅金（沿用主色）／已加密檔案＝深綠（新增）** | 黃銅金是整個 App 已定案的主色（信封邊框、蠟封、金庫轉輪都用），密碼庫沿用其中一色能維持同一個 App 家族的觀感；深綠是傳統帳本／分類帳常見的封面色，跟黃銅金搭配有典故（老式帳本綠皮+燙金）。橘色被排除：跟既有暗紅蠟封（警告/找不到指標檔的語意色）在色輪上太接近，容易造成語意混淆；藍色被排除：完全是外來色，跟信封/金庫的暖色調世界脫節 |
| 分類標籤選中/未選中狀態 | **不另外畫圖檔**，選中＝往外凸出、飽和度拉滿、陰影加深；未選中＝往內收、降低飽和度——都用 CSS `transform`／`opacity` 處理 | 位置/陰影/透明度差異用程式碼就能做出來，畫兩套圖檔是不必要的重複工作 |
| 密碼顯示/隱藏的圖示 | **維持現有的通用眼睛圖示，不套用筆記本主題**（便利貼提案已撤回） | 便利貼縮小到清單列的實際尺寸後辨識度不夠，「點一下掀便利貼＝看密碼」也不夠直覺；眼睛圖示是幾乎所有軟體通用的強慣例，使用者已有肌肉記憶，不是每個小圖示都要塞進筆記本比喻裡，比喻只適合套在撐得起細節、或沒有強烈既有慣例的地方 |
| TOTP 倒數怎麼呈現 | ~~沿用既有圓環邏輯（`totpRingStyle`），疊在懷錶造型錶面外圈~~——**這條已被下一輪修正取代，見下一列** | 圓環已經是驗證過可讀性的既有實作，換皮不換邏輯風險最低；指針掃動要另外寫「角度隨時間更新」的邏輯，且指針視覺上比圓環更難一眼判斷剩餘比例 |
| TOTP 倒數呈現（修正版，接進側欄殼子那輪定案） | **改成實心扇形（披薩切片），不是空心圓環**，用 CSS `conic-gradient` 畫，疊在懷錶錶面中央、跟金色外框圈之間留出可辨識的間隙（不貼齊外框） | 實作 `11-notebook-password-locker.html`／`14-notebook-in-shell.html` 時，使用者更新了 `Notebook_Pocket_Watch.svg` 素材（改成金色外框圈+灰色錶面），套用原本的圓環邏輯後發現兩個問題：①圓環顏色跟素材本身的金色外框幾乎同色，疊在外框上「金疊金」完全看不出進度；②改貼齊錶面內緣後，使用者又回饋圓形太貼近外框、兩者顏色帶過去「若有似無」。改成實心扇形＋跟外框留間隙，兩個問題一起解決：扇形疊在灰色錶面（不是金色外框）上，對比度足夠；縮小尺寸留出間隙後，扇形本身讀成一個獨立飄在錶面中央的指示器，不會被外框的顏色吃掉輪廓。**`totpRingStyle` 這個既有的圓環邏輯本身不需要改**（連續／逐秒平滑消耗、`TOTP_RING_WARNING_THRESHOLD_SECONDS` 警示色邏輯都維持，見下一列）——變的只是最外層怎麼把「剩餘比例」這個數字畫成圖形，從 SVG stroke 圓環換成 `conic-gradient` 扇形，資料/邏輯層完全不受影響 |
| 圓環（現在是扇形）要不要改成對應 12 刻度的分段跳動 | **不要，維持連續／逐秒平滑消耗** | 這是使用者拿來判斷「還剩多少時間可以複製驗證碼」的功能性指標，不是裝飾動畫；已有 `TOTP_RING_WARNING_THRESHOLD_SECONDS=5` 的既有警示色邏輯，分段跳動在最後幾秒的精確度不夠，讀起來不安心。金庫轉盤那種「有段落感」的機械頓挫適合一次性動作（鎖上瞬間），不適合套用在需要持續盯著判讀的即時倒數上——動態語言要服務實際功能，不是為了統一而統一 |
| TOTP 驗證碼數字本身要不要顯示 | **要**，獨立一個固定寬度欄位顯示三碼一組的數字（例如「482 913」），不是只有扇形/圓環這個時間指示器 | 上一輪決策記錄只定案了「剩餘時間怎麼呈現」，沒有涵蓋「驗證碼本身的數字要不要顯示」這件事——這輪實作 mockup 時使用者發現這個缺口：只看到轉圈圈的視覺，看不到真正要複製的驗證碼。三碼一組（不是六碼連在一起）是跟簡訊驗證碼／Authenticator App 一致的既有排版慣例 |
| 懷錶錶面的刻度數量 | **12 個粗刻度，不加細**（曾經畫過更細緻的刻度版本，最後放棄） | 這個元素實際顯示尺寸不大（清單列旁邊的小圖示，約 32-48px 量級），刻度太細縮小後會糊成一片；圓環本身已定案平滑不分段，刻度純粹裝飾，沒必要為了裝飾犧牲小尺寸下的清晰度 |
| 新增帳密的入口素材 | **鋼筆**（不是鉛筆），白／珍珠光澤筆身＋兩圈金色裝飾環（筆蓋、握筆處各一圈）＋金屬筆尖 | 最早畫過木紋筆身配金屬鋼筆尖的版本，材質語言矛盾（木頭鉛筆不會裝金屬鋼筆尖）；後改成滑順珍珠光澤筆身解決材質矛盾；加上兩圈金色裝飾環是為了跟其他素材的黃銅金主色調牽上關係——這是目前素材庫裡唯一一個底色是冷色系（白/銀）的素材，金色裝飾環讓它不會顯得像來自別的 App |

## 接入側欄殼子（第二輪，已定案）

上一輪留下三個「待確認」，這輪（配合 `13-sidebar-ticket-shell.html` 側欄殼子定案後）一次問清楚，
連帶把筆記本 mockup（`11-notebook-password-locker.html`）怎麼接進側欄殼子的框架也一併定案。

### 決策記錄

| 決策點 | 結論 | 理由 |
|---|---|---|
| 其他既有功能性元素（搜尋框、排序、CSV 匯入匯出按鈕、設定子分頁）要不要套進筆記本語彙 | **不套，維持中性風格** | 跟眼睛圖示同樣的判斷標準：這些是高頻率操作的功能性控制項，不是撐得起細節、或沒有強烈既有慣例的地方，硬套比喻反而犧牲辨識度 |
| 深色模式下筆記本內頁的顏色 | **另外匯出一套深色版素材**，不用 CSS filter 湊合 | 螺旋線圈／橫線是燒進 SVG 的圖形內容，不是 CSS 可以直接調色的東西；`invert` 類濾鏡套到整張圖上，連本來就有顏色語意的地方（分類標籤／懷錶）也會被一起反轉，不精準。深色版素材已經匯出並放進 `assets/Notebook_Body_Drack.svg`（viewBox／座標系跟淺色版 `Notebook_Body.svg` 完全一致，可以直接沿用同一組量測數字，見技術規格文件）；分類標籤（黃銅金／深綠）跟懷錶維持原色不換深色版，理由跟原本定案一致——它們在深色背景上本來就夠醒目 |
| 筆記本這張「整頁圖」怎麼回應實際可用寬度變化（側欄可收合、視窗可拉寬拉窄） | **保持正方形比例縮放**，寬度不夠就整張筆記本一起縮小 | `.notebook-outer{width:min(760px,100%);aspect-ratio:1}`，維持跟信封／金庫 mockup 同一個「容器永遠正方形，避免 `object-fit:contain` 形變」的原則；文字/圖示會跟著縮小，但整張筆記本的完整形狀不會被裁切或需要橫向捲動 |
| 清單筆數超過內頁横線數量（18 條，扣掉標題／工具列大約剩 13-14 行）時的行為 | **真正分頁**，一頁固定額度的行數，超過就翻頁；搜尋/篩選後的結果也走分頁，不直接列出所有符合項目 | 沿用 mockup 原本就有的「上一頁／1｟3／下一頁」分頁器概念，只是要接上真正的分頁邏輯，不是純視覺展示 |
| 「關聯到現有帳號」「設定」這兩個既有入口放哪 | **設定用 `.tabs` 子分頁**（清單／設定，比照 `13-sidebar-ticket-shell.html` 的 `.tabs` 寫法）；**「關聯到現有帳號」跟「新增帳密」並列放進工具列按鈕** | 跟已定案的 `activeVaultSubTab`（清單/設定）架構一致；關聯到現有帳號是獨立於新增表單的入口（見 `CONTEXT.md`〈選擇密碼〉），工具列是它目前在其他地方的既有位置 |
| 「設定」子分頁的視覺容器 | **完全跳出筆記本方形畫布，改成中性風格的一般頁面** | 設定頁面（密碼／Passkey／恢復金鑰／CSV／部件管理）本身屬於「其他功能性元素維持中性」那條決策管轄範圍；跳出畫布也避免把大量表單硬塞進固定 760×760 正方形空間裡造成擁擠 |
| 側欄 `.page-head` 標題跟筆記本畫布自己的 HTML 標題重複，怎麼處理 | **兩個都保留**，垂直疊在一起 | 跟 `13-sidebar-ticket-shell.html` 既有模式一致（側欄項目「加密」+ 頁面大標題「加密」本來就並存）；筆記本畫布自己的標題另外有實際作用——側欄收合成只剩圖示、沒有文字標籤時，畫布自己的標題文字是使用者唯一能直接讀到「密碼庫」這三個字的地方，接受垂直空間被佔兩次的取捨 |

### 待確認（下一輪處理）

- 這份 mockup（連同接進側欄殼子的整合版）目前／預計仍是純靜態展示搭配基本的分頁/深淺色切換，沒有接任何真正的搜尋、排序、TOTP 動態更新、密碼顯示隱藏的即時邏輯——實際串接 Vue 元件時才會補上。
- 標籤選中/未選中目前只有 CSS 兩種狀態展示，沒有點擊切換分類的完整互動。
- CSV 匯入匯出、部件管理等設定頁內部的具體表單排版還沒有實際畫出來，只定案了「這些內容跳出筆記本畫布、走中性風格頁面」這個大方向。

# FileLocker v2.0.0

## 繁體中文

新增「獨立加密」（單檔案分散式加密，`.flocked`）完整功能、CLI 全面英文化＋使用體驗現代化，以及密碼庫 TOTP 動態驗證碼與瀏覽器擴充功能。這輪變更量大，因此跳 major 版號。

### 亮點

- **新增：獨立加密（單檔案分散式加密）**
  - 加密時新增一個每次可勾選的選項（UI 顯示為「獨立加密」），選擇不把加密內容存進集中管理的 Vault，改成原地（或使用者指定的位置）留下一顆自帶完整密文的 `.flocked` 檔案，不產生 `.locked` 指標檔——不依賴 Vault 也能獨立攜帶，把 `.flocked` 搬到別的資料夾之後雙擊仍然能正常解密。
  - `.flocked` 檔頭採用可擴充格式（Magic + 版本號 + 長度欄位 + UUID + 保留位元組），未來要加欄位不會跟舊版檔案不相容。
  - 沒有集中備份，`.flocked` 遺失即資料永久遺失，勾選時會用紅色警示對話框明確提醒這個取捨（每次勾選都會提示，不是只提示一次）。
  - GUI（右鍵加密、App 內加密頁籤、雙擊 `.flocked` 直接解密、清單頁「前往檔案原始位置」按鈕）與 CLI（`--standalone`／`--destination`）同步支援。
- **CLI：全面英文化＋使用體驗現代化**
  - 全站訊息（含錯誤代碼翻譯）新增英文版本，跟隨系統語言，或用全域 `--lang <zh-TW|en>` 旗標指定，任何指令、任何參數位置都適用。
  - 新增子命令寫法：`encrypt`／`unlock`／`unlock-recovery`／`list`／`delete`（不帶開頭 `--`），對照主流 CLI 工具的「動詞當子命令」慣例；舊的 `--encrypt` 等旗標寫法完整保留、行為不變，用到時印一行過時提醒到 stderr，不強制淘汰。
  - 新增 `-h`／`--help`、`--version`、`--dry-run`／`-n`（`--delete` 適用，只預覽不執行）、`--yes` 短別名 `-y`。
  - 新增 `--output`／`-o <text|json>`：`json` 模式下所有指令都印一份結構化 JSON 到乾淨的 stdout，方便腳本直接 parse，其餘資訊性文字改印到 stderr。
  - 新增 `FileLocker.Cli completion <bash|zsh|pwsh>` 印出對應 shell 的自動完成腳本。
  - 成功／失敗訊息依終端機偵測決定要不要上色，尊重 `NO_COLOR` 環境變數；加解密執行中顯示忙碌旋轉指示器，兩者在 JSON 模式或輸出被導向檔案/管線時自動關閉。
- **密碼庫：新增 TOTP 動態驗證碼與瀏覽器擴充功能**
  - 密碼庫項目可額外儲存 TOTP 密鑰，App 內顯示即時更新的動態驗證碼。
  - 新增瀏覽器擴充功能（透過 Native Messaging Host 跟主程式溝通），可在網站上自動填入帳密與 TOTP 驗證碼。
- **一批 GUI 造型改版**：信封蠟封加密/解密流程、金庫門轉輪動畫、側欄與票根清單造型定案並全面實作，新增視窗控制鈕造型設定（macOS／Windows 原生風／風格化版三種可選）。
- **修正一批這輪開發中發現的問題**：清單頁誤判「指標檔可能被移動或刪除」（`.flocked` 項目原本無條件用 `.locked` 的檢查方式）、解密頁籤手動選檔案不認得 `.flocked`、解密信封彈出後密碼輸入框沒有自動取得鍵盤焦點、`VaultChangeWatcher.Dispose()` 的競爭路徑。

### 已知限制

- **`.flocked` 沒有集中備份**：檔案本身就是唯一副本，遺失即資料遺失，這是「分散式」設計本身的必然取捨，不是缺陷。
- **`.flocked` 不支援手動重新關聯路徑**：檔案被移走後只能靠使用者自己找到本體雙擊解密，清單頁不提供「選一個新路徑」的修正介面。
- **檔案總管雙擊 `.flocked` 解密、`.flocked` 副檔名圖示顯示，尚待正式安裝環境的人工互動驗證**：程式碼與單元測試已完成，這兩項需要正式打包安裝程式並安裝到實機才能驗證，這次發布還沒有完整走過這個流程。
- **CLI 不涵蓋 Passkey**：設計決定，`KeyCredentialManager` 一定會跳出 Windows Hello 系統 UI，跟「無 GUI 環境可操作」的 CLI 存在目的直接衝突。
- **背景模式（系統匣常駐）下，主視窗與系統匣選單的實際彈出位置有時不如預期**（可能出現在螢幕角落而非預期位置），不影響功能本身可以正常開啟與操作；根因排查中。
- 安裝程式仍未申請數位簽章，執行安裝檔或更新下載回來的安裝檔時，Windows SmartScreen 可能會跳出警告，點「其他資訊」→「仍要執行」即可繼續。
- 軟體更新檢查需要能連上 GitHub（`api.github.com`），且僅支援透過正式安裝版比對版本；直接以原始碼執行的開發版不會顯示版本資訊。
- 密碼遺失無法復原，沒有任何後門機制——請務必妥善保存密碼與恢復金鑰。

## English

Added the full "Standalone Encryption" (per-file, no central Vault, `.flocked`) feature, a fully bilingual and modernized CLI, and TOTP + browser extension support for Password Locker. This release bundles enough change to warrant a major version bump.

### Highlights

- **New: Standalone Encryption (per-file, no central Vault)**
  - Encryption now has a per-use checkbox (labeled "Standalone Encryption" in the UI) to skip storing the encrypted content in the central Vault. Instead, a self-contained `.flocked` file is left in place (or at a destination you choose) — no `.locked` marker is produced. It doesn't depend on the Vault: move the `.flocked` file to another folder and double-clicking it still decrypts correctly.
  - The `.flocked` header uses an extensible format (magic bytes + version + length field + UUID + reserved bytes), so future fields won't break compatibility with files created by this version.
  - There is no central backup — losing the `.flocked` file means losing the data. A red confirmation dialog spells this out every time the option is checked (not just once per app lifetime).
  - Supported end-to-end in both the GUI (right-click encrypt, the in-app encrypt tab, double-click `.flocked` to decrypt, a "go to original location" button on the list page) and the CLI (`--standalone`/`--destination`).
- **CLI: full English localization + modernized UX**
  - All CLI messages (including translated error codes) now have an English version, following the system language by default or overridable with the global `--lang <zh-TW|en>` flag, usable with any command or before it.
  - New subcommand syntax: `encrypt`/`unlock`/`unlock-recovery`/`list`/`delete` (no leading `--`), matching the "verb as subcommand" convention of mainstream CLI tools. The legacy `--encrypt`-style flags remain fully functional and unchanged in behavior, printing a one-line deprecation notice to stderr — no forced removal timeline.
  - New `-h`/`--help`, `--version`, `--dry-run`/`-n` (for `--delete`, preview only), and `-y` as a short alias for `--yes`.
  - New `--output`/`-o <text|json>`: in `json` mode, every command prints one structured JSON document to a clean stdout for easy scripting, with all other informational text routed to stderr instead.
  - New `FileLocker.Cli completion <bash|zsh|pwsh>` prints a shell completion script.
  - Success/failure messages are colorized based on terminal detection and respect the `NO_COLOR` environment variable; encrypt/unlock show a busy spinner — both are automatically disabled in JSON mode or when output is redirected/piped.
- **Password Locker: TOTP codes and a browser extension**
  - Password Locker entries can now store a TOTP secret, with a live-updating code shown in the app.
  - A new browser extension (talking to the app via a Native Messaging Host) can autofill credentials and TOTP codes on websites.
- **A round of GUI visual redesign**: the wax-seal envelope encrypt/decrypt flow, the vault door reel animation, and the sidebar + ticket-list layout were finalized and fully implemented, plus a new window control button style setting (macOS-style, native Windows, or stylized — three options).
- **Fixed a batch of issues found during this round of development**: the list page falsely flagging "marker file may have been moved or deleted" for `.flocked` items (it previously always used the `.locked`-only check), manually selecting a `.flocked` file on the Decrypt tab not being recognized at all, the decrypt envelope's password field not auto-focusing on open, and a race condition in `VaultChangeWatcher.Dispose()`.

### Known limitations

- **`.flocked` has no central backup**: the file itself is the only copy — losing it means losing the data. This is an inherent trade-off of the "distributed" design, not a defect.
- **`.flocked` doesn't support re-linking a moved path**: if the file is moved, you have to locate it yourself and double-click it to decrypt — the list page offers no "pick a new path" repair flow.
- **Double-click decryption of `.flocked` from Explorer, and its file-type icon, still need manual verification on a real installed build**: the code and unit tests are complete, but these two require a packaged installer on a real machine to verify, and that full pass hasn't happened yet for this release.
- **The CLI doesn't support passkeys**: a deliberate design decision — `KeyCredentialManager` always pops up the Windows Hello system UI, which directly conflicts with the CLI's reason for existing (usable in headless/no-GUI environments).
- **In background mode, the main window and tray menu don't always pop up exactly where expected** (occasionally in a screen corner) — this doesn't affect the app opening or working normally; the root cause is still being investigated.
- The installer still isn't code-signed — Windows SmartScreen may warn when running the installer or an update package you just downloaded; click "More info" → "Run anyway" to continue.
- The update check requires reaching GitHub (`api.github.com`) and only works from an installed build; running from source shows no version info.
- A lost password cannot be recovered — there is no backdoor. Keep your password and recovery key safe.

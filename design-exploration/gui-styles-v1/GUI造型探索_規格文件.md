# FileLocker GUI 造型探索（第 1 輪）

## 目的與背景

FileLocker 目前的介面（`src/FileLocker.Web/src/App.vue`）是專案早期定下的排版，沒有經過系統性
的風格比較。這一輪的目的是在動任何既有程式碼之前，先用五種明顯不同的排版語彙做出同一個代表畫面，
讓使用者實際比較、選出未來的調整方向，再據此延伸設計其餘分頁並回頭改動真正的 Vue 元件。

這輪只做造型比較，**不涉及功能邏輯**，也不動 `main` 分支上既有的程式碼——五版都是獨立的靜態
HTML／CSS 檔案，開在瀏覽器就能看，不需要跑 `npm run dev` 或 `dotnet run`。

## 涵蓋範圍

- **代表畫面**：「已加密清單」分頁（`list.title`）。選這頁是因為它同時涵蓋標題列、分頁籤／子分
  頁籤、搜尋、清單/表格、批次群組、狀態徽章（巢狀鎖定、找不到指標檔的警告）、多種解鎖操作按鈕
  （解密／Passkey／恢復金鑰）——最能一次展現排版風格在「密集資訊 + 多操作入口」情境下的表現。
  其餘分頁（加密、解密、資料夾防護、密碼庫、設定）留到使用者選定方向後才延伸製作，理由是先驗證
  一個複雜畫面比五個分頁各做一次淺層版本更能反映真實可用性。
- **假資料**：六筆項目（PDF、資料夾、批次群組、含巢狀鎖定的壓縮檔、憑證檔、一筆缺指標檔的警告
  項目），五版共用同一組資料，確保比較的是排版本身、不是內容差異。
- **實作方式**：純靜態 HTML + 內嵌 CSS，不用 Vue／不接 IPC／不讀翻譯檔——文字目前只有繁體中文
  一份（比較階段用），選定方向、正式移植回 `App.vue` 時才會依照 CLAUDE.md 的規則補上英文並改成
  `t('key')` 呼叫。

## 如何預覽

直接用瀏覽器開啟以下任一檔案即可，不需要啟動任何開發伺服器：

```
design-exploration/gui-styles-v1/1-design-site.html
design-exploration/gui-styles-v1/2-social-app.html
design-exploration/gui-styles-v1/3-apple-native.html
design-exploration/gui-styles-v1/4-windows-native.html
design-exploration/gui-styles-v1/5-fusion-original.html
```

以上五版都已經用 Playwright 截圖走查過一次排版（1280×860 視窗），確認沒有文字被裁切、按鈕文字
換行、色塊套錯顏色等明顯排版問題（造型 2 的行內圖示按鈕原本因為固定正方形尺寸把「解密」「恢復
金鑰」這種帶文字的按鈕擠成兩三行，已經改成依內容自動撐開寬度、純圖示按鈕才維持正方形）。

## 五版逐一說明

### 造型 1：設計至上／UX 優秀網站風（`1-design-site.html`）

參考 Linear／Stripe／Vercel 這類設計導向 SaaS 儀表板的排版慣例。

- **導覽**：左側固定側欄，文字為主、極少邊框，用留白分組（工作區／系統兩組），選中項目用淺色
  底 + 品牌色文字，不用色塊或圖示強調。
- **色彩**：中性灰階為主（`#F7F7F9` 背景、`#FFFFFF` 卡片），單一靛藍強調色 `#5B5BF0`，跟現有
  App 的金色主色刻意不同——這版的目的是展示「設計網站」語彙本身，不是套用既有品牌色。
- **字體**：Inter（設計網站的事實標準字體），標題字重 650、字距收緊（`letter-spacing:-.02em`）。
- **版面**：卡片化表格（表格本身包在一張白色圓角卡片裡，跟頁面背景區隔），分頁籤用膠囊狀
  segmented control，操作按鈕是細邊框小按鈕，hover 時邊框變強調色。
- **與現有 App 的差異**：現有 App 沒有「卡片包住表格」這層視覺區隔，表格是直接貼在頁面背景上；
  這版額外的卡片陰影/圓角讓內容區域邊界更清楚，是這五版裡跟原本落差最小、最容易漸進套用的一版。

### 造型 2：吸引用戶的社交軟體風（`2-social-app.html`）

參考 Discord／Instagram／Spotify 一類社交／串流 App 的排版慣例：深色預設、圖示化導覽、卡片feed。

- **導覽**：最窄的圖示式側欄（84px），只有圖示沒有文字，選中項目左側有一條漸層色標，底部放大頭貼。
- **色彩**：深色背景（`#0F1013`），漸層強調色（品紅→紫），每個檔案類型給不同色相的圖示底色，
  整體比其他四版更「有表情」，跳脫工具軟體慣用的中性灰。
- **字體**：Poppins（偏圓潤、社交產品常用字體）。
- **版面**：拿掉表格，改用「摘要卡＋feed 卡片」——頂部三張圓環統計卡（全部項目／Passkey／需要
  留意），下面每個檔案是一張獨立圓角卡片而不是表格列，操作按鈕做成圓角圖示按鈕。
- **與現有 App 的差異**：這版改動幅度最大——現有 App 全部用表格呈現清單，這版整個拿掉表格，
  這也是刻意的：目的是展示「假如完全捨棄表格」的另一種資訊架構長什麼樣子，讓使用者知道這個
  方向的代價（同樣六筆資料，卡片版占的垂直空間明顯比表格版多，資料多的時候要捲動更久）。

### 造型 3：Apple 原生軟體風（`3-apple-native.html`）

參考 macOS Finder／系統設定 App 的排版慣例。

- **視窗**：畫出完整的紅黃綠三色交通燈視窗控制項 + 置中視窗標題列，模擬原生視窗外觀（實際
  WPF+WebView2 環境不會有這層，這裡畫出來是方便使用者直接感受「這是一個原生 macOS 視窗」的
  完整語境，正式套用時這層會被拿掉，交給作業系統自己的視窗框）。
- **導覽**：210px 側欄，`backdrop-filter:blur()` 做出毛玻璃效果，選中項目是實心藍色圓角矩形
  （系統藍 `#007AFF`），跟 macOS 系統設定的側欄選中樣式一致。
- **字體**：`-apple-system` 字體堆疊（實際會顯示 SF Pro），字級普遍比其他四版小一階
  （工具列 13px、表格內容 12.5px）——Apple 原生軟體的資訊密度慣例本來就比一般網頁緊湊。
- **版面**：表格化清單，但用最細的分隔線（`#EFEFF0`）取代明顯的框線，hover 用淺藍底
  （系統選取色的淡化版）而不是灰底，符合 macOS 清單 hover 的視覺慣例。
- **與現有 App 的差異**：現有 App 是自繪標題列（見 `MainWindow.xaml` 的 `Margin="6"` workaround，
  CLAUDE.md 記錄過這是為了閃避無邊框視窗跟 WebView2 airspace 問題），這版示範的是「假如改回
  系統原生標題列＋毛玻璃側欄」的樣子，兩者是有實作代價落差的方向，不是純 CSS 改動就能達成。

### 造型 4：Windows 原生軟體風（`4-windows-native.html`）

參考 Windows 11 Fluent／WinUI 3（設定、檔案總管一類原生 App）的排版慣例。

- **視窗**：畫出 Windows 11 風格的標題列（最小化/最大化/關閉三個方形圖示按鈕，右上角），
  跟造型 3 的 macOS 交通燈對照，同樣是「展示語境用，正式套用時交給系統」的性質。
- **導覽**：NavigationView 慣用的左側導覽，選中項目是淺灰底 + 左側 3px 強調色細線（不是整塊
  色底，這是 WinUI 3 NavigationView 選中態的實際樣式特徵）。
- **色彩**：Windows 系統藍 `#0078D4`，背景用 Windows 11 的 Mica 灰白色 `#F3F3F3`。
- **字體**：Segoe UI Variable（Windows 11 系統預設字體）。
- **版面**：麵包屑（`FileLocker > 已加密清單`）+ CommandBar（一排帶圖示的指令按鈕，主要動作用
  實心藍底）+ Pivot 分頁籤（底線樣式，不是膠囊）+ 底部狀態列（顯示項目數與空間用量）——這些都是
  Windows 原生應用程式清單頁常見、但目前 FileLocker 沒有的元素。
- **與現有 App 的差異**：這版新增了「麵包屑」跟「底部狀態列」兩個現有 App 完全沒有的資訊區塊，
  是這五版裡額外資訊密度最高的一版；是否要採用這兩個新區塊本身也是後續要跟使用者確認的獨立
  決策，不是「選了 Windows 風格」就自動代表要一起採用。

### 造型 5：融合／原創風「保險箱」（`5-fusion-original.html`）

不對應單一參考來源，是以 FileLocker 既有的品牌意象（保險箱／封套／鎖）為出發點做的原創方向，
刻意跟前四版的既有典範拉開距離，用來當作「如果不套用任何現成典範，自己的產品能長成什麼樣子」的
對照組。

- **導覽**：拿掉側欄，改成頂部一整排藥丸狀分頁籤（`chip-nav`），視覺上呼應「保險箱轉盤刻度」的
  意象，是五版裡唯一沒有側欄的版本。
- **色彩／材質**：暖色調（米色背景 `#FBF7F0` + 極淡的圓點紋理），沿用現有 App 真正在用的金色主
  色 `#A8770F`（跟造型 1-4 刻意不用品牌色不同，這版反而是刻意延續，因為這是「原創延伸」而不是
  「展示某個外部典範」）。
- **字體**：標題用襯線字體 Fraunces（襯線體在其餘四版、以及現有 App 裡都沒出現過，用來強化
  「這是一個獨立產品方向」而不是網頁儀表板或系統設定頁的既視感），內文維持沿用 IBM Plex Sans
  避免整頁都變得太裝飾性、犧牲可讀性。
- **版面**：Bento 卡片網格（三欄），每張卡左側一條金色直條表示鎖定狀態、右上角一個虛線圓圈徽記
  （`seal-stamp`，呼應信封蠟封的意象），批次群組用跨三欄的長條卡片呈現。
- **已知取捨**：卡片式版面跟造型 2 一樣，同樣資料筆數會占用更多垂直空間；虛線圓圈徽記在項目
  很多時可能顯得重複而失去強調效果，這點需要放進更多真實資料量測試才能確認是否成立。

## 決策記錄

| 決策點 | 結論 | 原因 |
|---|---|---|
| 涵蓋範圍先做一頁還是六頁 | 先做「已加密清單」一頁代表畫面 | 避免五種風格 × 六個分頁的組合爆炸，選定方向後才有必要延伸其餘分頁；使用者已確認（見對話紀錄） |
| 實作方式：靜態 HTML 還是 Vue 元件 | 靜態 HTML／CSS，不接 Vue | 純造型比較階段不需要承擔元件化、假資料串接的額外工作量；使用者已確認 |
| 第五版的定位 | 融合／原創，不對應單一參考來源 | 使用者列的四種參考（設計網站／社交軟體／Apple／Windows）本身就是四個既有典範，若第五版只是拆分其中一種會少了「跳脫既有典範」這個比較維度；使用者已確認 |
| 分支策略 | 開新分支 `explore/gui-styles`，跟批次 2 進行中的換源工作分開 | 批次 2 的改動（`FileLocker.Web` 換源到共用套件）在探索造型當下還沒 commit，兩件事完全獨立、不應該混在同一個工作樹狀態裡比較 |

## 已知限制

- 五版都只做了「已加密清單」這一頁，尚未驗證同一套風格套用到「加密」「解密」「資料夾防護」
  「密碼庫」「設定」這幾個資訊結構明顯不同的分頁時是否依然成立（例如加密頁的拖放區、密碼庫的
  表單彈窗，在造型 2 的卡片式或造型 5 的 Bento 網格下會長什麼樣子，目前未知）。
- 造型 3、造型 4 畫出的視窗框（交通燈／WinUI 標題列）只是展示語境用，實際套用到 WPF+WebView2
  環境時這層由作業系統或既有的自繪標題列機制負責，不是這幾個 HTML 檔案裡的 CSS 決定的。
- 五版目前只有繁體中文文字、沒有淺色/深色模式切換、沒有實際鍵盤導覽／`:focus-visible` 樣式、
  沒有响應式窄視窗測試——這些都是比較階段刻意省略的細節，選定方向、正式移植回 `App.vue` 時
  才需要依 CLAUDE.md「UI 變更注意事項」的四點檢查一併補上。
- 假資料是手刻的靜態文字，沒有測試過極端情況（超長檔名、超多批次項目、清單為空的空狀態在五種
  風格下分別長什麼樣子）。

## 待辦事項

- 使用者選定方向後，延伸設計其餘五個分頁（加密／解密／資料夾防護／密碼庫／設定）的靜態版本，
  供再次確認排版後才動手改 Vue 元件。
- 選定方向後，補上深色模式配色（目前只有造型 3 隱含淺色系統慣例、其餘四版都只做了一種配色，
  沒有對應現有 App 的 light/dark 雙主題機制）。
- 選定方向後，正式移植回 `src/FileLocker.Web/src/App.vue` 時，所有文字要改成 `t('key')` 呼叫並
  同步補上 `zh-TW.json`／`en.json` 兩份翻譯（目前這五個 HTML 檔案的文字是寫死的繁體中文，只服務
  這輪的造型比較，不是最終要交付的程式碼）。

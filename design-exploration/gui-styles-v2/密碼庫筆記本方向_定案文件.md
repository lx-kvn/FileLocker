# FileLocker GUI 造型探索——密碼庫「筆記本」方向定案

## 背景

信封（加密/清單/解密）、金庫門（資料夾防護）兩個方向定案後，密碼庫這輪延伸第三種視覺語彙——原因是密碼庫的操作性質（查閱、記錄、翻找）跟前兩者完全不同：信封是「裝東西寄出」、金庫是「限制空間進出」，密碼庫則是「持續查閱/記錄的筆記」，硬套前兩者的比喻都不合適，需要獨立的語彙。

密碼庫實際功能結構（`packages/password-locker-ui/src/PasswordLockerPage.vue`）：兩個分類（`Website` 網站帳密／`EncryptedFile` 已加密檔案）、每筆帳密可選配 TOTP（既有一組圓環倒數邏輯 `totpRingStyle`）、可關聯多個網域、有搜尋/排序、新增編輯表單。這份文件記錄跟使用者討論筆記本方向時，一輪一輪來回調整、邊討論邊畫的決策脈絡。

## 決策記錄

| 決策點 | 結論 | 理由 |
|---|---|---|
| 密碼庫的視覺語彙 | **筆記本**（螺旋線圈裝訂＋橫線內頁） | 密碼庫是查閱/記錄性質，跟信封「寄出」、金庫「限制進出」的動作性質不同，需要獨立的第三種語彙 |
| 整體容器要不要畫成闔上的封面 | **不要，直接用打開的內頁**（螺旋線圈＋米白橫線紙，中性色） | 最早畫過深咖啡皮革封面（含「PASSWORD NOTES」字樣），但深色封面當整頁背景，跟上面要疊的搜尋框/清單/表單這些高資訊密度控制項對比不夠、可讀性有風險；米白橫線內頁淺色、對比度好，撐得住功能性 UI；封面上烤死的英文字也違反雙語規則（所有文字要走 `t('key')`），標題交給前端疊字 |
| 內頁橫線的附帶用途 | 如果清單列高度跟橫線間距一致，**清單分隔線可以直接借用橫線本身**，不用另外疊 CSS `border-bottom` | 避免「畫一個筆記本樣子的背景」+「另外浮一層普通表格」這種兩張皮的違和感 |
| 兩個分類的顏色 | **網站帳密＝黃銅金（沿用主色）／已加密檔案＝深綠（新增）** | 黃銅金是整個 App 已定案的主色（信封邊框、蠟封、金庫轉輪都用），密碼庫沿用其中一色能維持同一個 App 家族的觀感；深綠是傳統帳本／分類帳常見的封面色，跟黃銅金搭配有典故（老式帳本綠皮+燙金）。橘色被排除：跟既有暗紅蠟封（警告/找不到指標檔的語意色）在色輪上太接近，容易造成語意混淆；藍色被排除：完全是外來色，跟信封/金庫的暖色調世界脫節 |
| 分類標籤選中/未選中狀態 | **不另外畫圖檔**，選中＝往外凸出、飽和度拉滿、陰影加深；未選中＝往內收、降低飽和度——都用 CSS `transform`／`opacity` 處理 | 位置/陰影/透明度差異用程式碼就能做出來，畫兩套圖檔是不必要的重複工作 |
| 密碼顯示/隱藏的圖示 | **維持現有的通用眼睛圖示，不套用筆記本主題**（便利貼提案已撤回） | 便利貼縮小到清單列的實際尺寸後辨識度不夠，「點一下掀便利貼＝看密碼」也不夠直覺；眼睛圖示是幾乎所有軟體通用的強慣例，使用者已有肌肉記憶，不是每個小圖示都要塞進筆記本比喻裡，比喻只適合套在撐得起細節、或沒有強烈既有慣例的地方 |
| TOTP 倒數怎麼呈現 | **沿用既有圓環邏輯（`totpRingStyle`），疊在懷錶造型錶面外圈**，不改指針掃動 | 圓環已經是驗證過可讀性的既有實作，換皮不換邏輯風險最低；指針掃動要另外寫「角度隨時間更新」的邏輯，且指針視覺上比圓環更難一眼判斷剩餘比例 |
| 圓環要不要改成對應 12 刻度的分段跳動 | **不要，維持連續／逐秒平滑消耗** | 這是使用者拿來判斷「還剩多少時間可以複製驗證碼」的功能性指標，不是裝飾動畫；已有 `TOTP_RING_WARNING_THRESHOLD_SECONDS=5` 的既有警示色邏輯，分段跳動在最後幾秒的精確度不夠，讀起來不安心。金庫轉盤那種「有段落感」的機械頓挫適合一次性動作（鎖上瞬間），不適合套用在需要持續盯著判讀的即時倒數上——動態語言要服務實際功能，不是為了統一而統一 |
| 懷錶錶面的刻度數量 | **12 個粗刻度，不加細**（曾經畫過更細緻的刻度版本，最後放棄） | 這個元素實際顯示尺寸不大（清單列旁邊的小圖示，約 32-48px 量級），刻度太細縮小後會糊成一片；圓環本身已定案平滑不分段，刻度純粹裝飾，沒必要為了裝飾犧牲小尺寸下的清晰度 |
| 新增帳密的入口素材 | **鋼筆**（不是鉛筆），白／珍珠光澤筆身＋兩圈金色裝飾環（筆蓋、握筆處各一圈）＋金屬筆尖 | 最早畫過木紋筆身配金屬鋼筆尖的版本，材質語言矛盾（木頭鉛筆不會裝金屬鋼筆尖）；後改成滑順珍珠光澤筆身解決材質矛盾；加上兩圈金色裝飾環是為了跟其他素材的黃銅金主色調牽上關係——這是目前素材庫裡唯一一個底色是冷色系（白/銀）的素材，金色裝飾環讓它不會顯得像來自別的 App |

## 資產命名

| 檔名 | 對應內容 | 備註 |
|---|---|---|
| `Notebook_Body.svg` | 筆記本內頁本體（螺旋裝訂＋橫線紙，中性色，不分類別） | 整個密碼庫分頁的容器底圖，對應信封的 `Envelope_Body.svg` |
| `Notebook_Tab_Website.svg` | 分類標籤——網站帳密（黃銅金） | 檔名對應程式碼裡的分類值 `Website`，不用中文猜測名稱 |
| `Notebook_Tab_EncryptedFile.svg` | 分類標籤——已加密檔案（深綠） | 對應程式碼裡的分類值 `EncryptedFile` |
| `Notebook_Pocket_Watch.svg` | TOTP 動態驗證碼的懷錶造型錶面 | 取代現有的通用圓環外框，圓環動畫邏輯本身不變 |
| `Notebook_Pen.svg` | 新增帳密用的鋼筆 | 白／珍珠光澤筆身＋金色裝飾環 |

五個檔案已經放進 `assets/`（連同 `.af` 原始檔），命名跟上表一致，已確認過。

## 待確認（下一輪處理）

- 密碼庫清單其他既有元素（搜尋框、排序、CSV 匯入匯出、設定子分頁）要不要也套進筆記本語彙，或維持中性風格——這輪只確認了清單本體＋分類標籤＋ TOTP ＋新增入口，沒有問到其他元素。
- 深色模式下這套配色（米白內頁、黃銅金/深綠標籤、白色鋼筆）怎麼處理，還沒問到——信封那邊深色模式的處理方式（牛皮紙換深皮革色、紅蠟保留原色）不一定能直接套用，米白內頁在深色模式下換成什麼色需要另外定案。
- 完整的 HTML mockup（比照 `8-envelope-assembled.html`／`9-envelope-list.html`／`10-vault-door.html` 那樣組裝成可互動的靜態頁面）還沒開始做，這輪只完成了素材本身跟決策記錄。
